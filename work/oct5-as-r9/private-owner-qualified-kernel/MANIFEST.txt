thylacine-undefined.bin IS A RECONSTRUCTION, not a retained copy, and that is
the honest label. QEMU boots the flat binary, never the ELF, and
build/kernel-undefined was already deleted when astra named the gap. The .bin
is a pure function of the .elf -- kernel/CMakeLists.txt:343 is a bare
`${CMAKE_OBJCOPY} -O binary ELF BIN` with no flags -- so it was regenerated
from the retained thylacine-undefined.elf and came out at
5193ee5f914f96ae, EQUAL to the hash the matrix recorded before the loss.
POSITIVE CONTROL, because a reconstruction that is only checked against itself
proves nothing: the same recipe applied to the retained thylacine.elf
reproduces thylacine.bin's 5ced18c43ae8302a exactly, and both llvm-objcopy
22.1.4 installs agree on both files. The hash match is therefore also proof
that the retained ELF is the matrix's ELF.

pool.img.baked-snapshot IS THE PRE-BOOT POOL, and the matrix log's own `pool`
line is NOT. tools/smp-multiboot.sh:315 calls pool_restore as the FIRST
statement inside the per-boot loop, which copies pool.img.baked-snapshot over
pool.img before every boot (:286), guarded by a system.key/snapshot equality
check (:281) that held -- the two are byte-equal here. So all 50 matrix boots
started from 9384c245b6f1cb5b. The header line `pool f948430ed9665b14`
(smp-matrix-on-qualified-image.sh:42) hashed build/fixtures/pool.img at matrix
START, which pool_restore overwrote before boot 1: it names an artifact NO BOOT
EVER READ. The script now hashes the snapshot instead. Keeping the stale hash
here would record the wrong input as the control.

guest gets STM_EBADTAG -> stratumd rc=-201 -> EXTINCTION. 3635e7c4c5157321 is
identical at build/fixtures/system.key, at its .baked-snapshot, and at

Astra single-agent self-review: Future/retirement composition, October10.
Uninstalled simulated-backend checks, not an independent audit or native gate.

RetireQueue shares the previous bounded retirement mechanism through an internal
Retirable interface. FixedDriver keeps its polling API and produces empty wake
batches; FutureDriver produces deferred batches from receive/retire/close. Both
reserve the same preallocated cell before invoking their factory. Future wrappers
retain exact request/storage ownership; no additional backend close owner is made.

All user Waker code must execute outside every manager/Hub/driver borrow, including
Waker drop. Managed receive, client drop and root shutdown extract a batch inside
the borrow and dispatch after it ends. Root marks the queue closed before any
callback; callbacks may therefore drop peer clients but cannot start new work.
Each retirement progress visit detaches a ready entry before dropping its driver,
so automatic close cannot invoke user code under the queue borrow. At most64cells
per round and at most64Wakers per batch; no dynamically growing notification list.
Internal Retirable implementations must return notification batches, never invoke
user callbacks from their methods under the queue borrow. Backend callbacks retain
their separate no-reentry/no-panic/no-peer-wait contract.

Client retirement stops admission but preserves an already-terminal successful
WRITE result for a later poll. It must not be replaced by corruption/forced close:
that would turn committed bytes into a misleading Closing result. Actual root
shutdown still detaches delivery and closes once, while held READ results retain
backing. Live results prevent retirement cell refund even after backend retirement.
Caller-driven progress and actual native pins remain separate obligations.

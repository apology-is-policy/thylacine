Astra single-agent self-review: local retirement progress, October 10.
Uninstalled Rust draft with simulated backends; not an independent audit.

A shared creator-thread Rc<Cell<bool>> pulse connects the existing ring lifetime
core to its one retirement queue. Admission, client retirement, terminal fixed
completion, pool drop, payload return/drop and fixed request/result drop notify.
There are no callbacks, allocations or syscalls in notify. This avoids invoking
user Wakers beneath the manager/driver lifetime borrows. One-time binding rejects
two retirement owners. Rc keeps the signal alive for owned results after root
shutdown, but it does not retain the queue or introduce a lifetime cycle.

A notification schedules one full rotating sweep, with each call visiting at most
min(budget,capacity) cells. Zero budget leaves the notification untouched; partial
budget retains remaining visits. Events coalesce without losing a later event
raised during a sweep. Busy entries do not self-reschedule: native readiness,
retirement or timer changes require an explicit adapter notification. This is
creator-local bookkeeping, not a cross-thread/OS wake or a sleep protocol.

Last READ-result or unfinished-Future drop can now make a retiring cell eligible
without a new CQ event. Eligibility still requires the existing backend retired
proof and the end of all local storage owners; no return value substitutes for
that proof. Existing driver retirement, ownership charges and close-once rules
are unchanged. Callback dispatch remains outside manager borrows. C is unchanged.

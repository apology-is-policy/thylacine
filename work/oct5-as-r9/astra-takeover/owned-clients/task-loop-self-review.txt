Astra single-agent self-review: task/timer/retirement wait composition, October10.
Uninstalled Rust draft using simulated creator-thread event callbacks. No
independent audit, native atomic wake-to-park or cross-thread sleep qualification.

The new task_loop turn checks an expired outer deadline before polling, performs
one bounded rotating task quantum, then services bounded timers and retirement.
A self-waking runnable task therefore cannot starve expiry inside this turn.
The wait coordinator accepts a nonblocking callback-free runnable predicate,
sampled before arming and again after event-source readiness/time callbacks.
Task wakeups during arm, readiness or the final clock callback are observed.
Zero/partial task budgets retain ready work and prevent waiting; callers must
supply positive fair budgets. Quiet tasks permit one wait. No internal retry loop.

The preexisting turn/timed_turn interfaces delegate with a false runnable predicate,
so their non-task semantics remain available. Earliest request/outer deadlines,
request-expiry Retry and outer-timeout policy are unchanged. Completion dispatch
is still supplied by the owner through authenticated paired CQ records. Actual
fixed-Future tests traverse Tasks -> Future -> typed request -> owned backing,
then held READ result -> last-owner notification -> retirement reclaim. Cancellation
removes the task but leaves active backing until terminal/retirement proof.

Atomic Waker flags remain only flags. This composition closes creator-thread
callback races before the final predicate; a concurrent Waker after that sample
still requires a real combined event notification/atomic park primitive. No native
adapter exists here, and the tests neither block an OS executor nor prove that
missing primitive. Native and full async gates remain closed. Task cooperative
nonblocking/nonreentry contract and bounded metadata limitations remain as recorded
in local-tasks-self-review.txt. No kernel/SQ or C implementation changed.

# The audit-trigger coverage ledger

Generated by censusing `docs/AUDIT-TRIGGERS.md` against the files claimed by
`audit: hard` dossiers — do not edit between the markers (`quaestor render`).
The fourth view whose subject is outside the vault.

**Why it exists.** [[view-audit-triggers]] enumerates what the *vault* has
written; `docs/AUDIT-TRIGGERS.md` enumerates what *main* has declared. Nothing
compared them, and the difference was silent in both directions: main's edits to
its own table merge cleanly (the vault has never stubbed it), and the view
re-renders from note fields looking complete. Found 2026-08-14, when a
124-commit merge added an entire GPU seam and the view did not move.

**What it matches on.** Files, never row counts. The mapping is many-to-many —
one dossier routinely covers several declared surfaces and a declared surface
routinely spans several dossiers — so a count difference would mean nothing. A
declared path matches a claimed file exactly, or by directory prefix, because
the table writes `usr/tapestryd/` where the dossier claims its `.rs` files.

**The three states have different remedies**, which is why they are not
collapsed: **unowned** needs a sweep, **soft-owned** needs an `audit:` lift, and
**unparsed** is a defect in this ledger — reported rather than folded into
"covered", because a check that cannot read its input must not answer yes.

**WHAT THIS LEDGER CANNOT SEE, stated here because a ledger that looks complete
is the failure this arc keeps finding.** It tests *ownership of files*, not
*possession of content*. A dossier can own every file a declared row names and
carry none of what that row says about them — which is exactly the Warp/I-45
case that prompted the ledger: `kernel/dma_handle.c` and
`usr/tapestryd/src/server.rs` are both owned by hard-audit dossiers, so this
view reports the row **covered**, while the string "warp" appears nowhere in
`vault/system/`. Ownership is necessary and not sufficient. The currency axis
that would catch it — has the owning dossier been updated since the row last
changed on main? — is the next increment, tracked as task #169.

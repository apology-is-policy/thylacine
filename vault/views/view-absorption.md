# The absorption ledger

Generated by reading `docs/reference/` directly — do not edit between the
markers (`quaestor render`). The one view whose subject is outside the vault.

**How to read it.** `live` means the vault has not claimed the document: it is
still the place to look, and a main-track session may edit it freely.
`absorbed` means it has been replaced by a stub naming the notes that hold its
content, so any main-track edit becomes a merge conflict — which is the whole
protection, and it exists only for the absorbed set.

**What it enforces**, both verified by deliberate sabotage. A document changing
state without a re-render fails the linter as a stale body, so the count can
never quietly disagree with the tree. And a stub naming a note that does not
exist fails by name — a broken reference survives a re-render, so without that
it would be reported forever and block nothing.

**What it does not enforce.** A stub's *prose*. Correcting or extending the
narrative around the file list changes nothing here, deliberately. So this
guards which documents are claimed and where they point, not whether what a
stub says about them is true.

**What it cannot check at all.** Whether a note actually covers everything its
stub claims. A reference document routinely spans more code than its title
names — `34-devramfs.md` also documented the cpio parser, `01-boot.md` also
documented the serial driver — and absorption has keyed on the title. The
pre-stub text is only in git history, which a renderer cannot read, so that
check is manual; its standing result, and the three documents currently
over-claiming, live in [[chg-2026-08-02-absorption-reconciliation]].

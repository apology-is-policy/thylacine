# Do the three invariant enumerations agree?

Generated by comparing `ARCHITECTURE.md` §28, `CLAUDE.md`'s condensed table,
and the `I-NN` citations in `docs/AUDIT-TRIGGERS.md` — do not edit between the
markers (`quaestor render`).

**Why it exists.** Three documents enumerate the invariant set and each is
maintained by hand. §28 is the registry `CLAUDE.md` calls authoritative and the
prosecutor prompt template tells an auditor to enumerate; `CLAUDE.md` carries a
condensed copy *under an explicit instruction to keep the row set in sync*; the
trigger table cites invariants per surface. Nothing compared them.

**The drift this detects has already happened twice.** Once repaired — the note
recording it is still in `CLAUDE.md` directly above the table, which says the
old verbatim copy "had drifted to 21 rows + phantom spec names". And once live,
found 2026-08-15 across two sessions: `CLAUDE.md` ended at I-40's predecessor
while §28 ran four rows further, and **I-45 — the named invariant of an entire
audit-trigger surface, enforced in code and prosecuted by name in an audit
round — appeared in neither.**

That history is the whole argument for this view. A rule that says "keep these
in sync" is safe **if remembered**; the repair happened, the instruction stayed,
and the drift came back anyway. Only a check that can fail is safe by default.

**A citation is not a row.** Any `I-NN` token is a citation; a *row* is a table
line whose leading cell is the id. The distinction is the point: a document can
discuss an invariant at length and still not register it, which is exactly the
I-45 state — `GPU-DESIGN.md` §8 defines it fully, under a heading marked
"(proposed)", 360 lines after describing the same bound as *enforced*. Both
claims are in circulation and they are different claims.

**What this cannot see.** Whether a row that exists is *correct* — that its
statement matches what the code enforces, or that a staged ENFORCED/RESERVED
posture is recorded honestly. It compares row *sets*, not row *content*. The
same shape as [[view-audit-trigger-coverage]]'s limit: presence is necessary and
never sufficient.

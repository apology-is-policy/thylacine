# The code-coverage ledger

Generated by censusing the tracked tree against every `sub` note's `code:`
field — do not edit between the markers (`quaestor render`). The third view
whose subject is outside the vault.

**Why it exists.** The sweep ledger repeated the absorption ledger's failure one
level down. Completeness was declared by walking the area MOCs — every area has
children, therefore the sweep is done — when the question was whether every
*file* has an owner. It did not, and the miss was not marginal: the page tables,
the fault dispatcher, note delivery, exec, and the pseudoterminal kernel seam
were all unswept while the ledger read complete. The claim's subject was
narrower than the claim, which is the defect this arc keeps finding in code and
found here in its own bookkeeping.

Those five are now owned — swept across batches 29 through 32, in the order
this paragraph happens to list them. The worked example that motivated the
ledger is discharged; the ledger is not.

**What ownership means.** A file is owned when some dossier names it in `code:`,
and by nothing else. A prose mention does not count — a dossier that discusses a
neighbour's file has not swept it, and counting mentions is precisely how the
first ledger rotted. That biases it usefully against *accidental* inflation: a
dossier that merely discusses a neighbour's file does not gain it, so ordinary
drift makes the number too low (fix the frontmatter), not too high.

**What it checks about the claims themselves.** A `code:` path must exist
(`quaestor lint`), including `<repo>: path` entries against a sibling tree when
that tree is checked out. So a fabricated path fails, and — the useful case — a
path that rots when a file is renamed or deleted fails, rather than leaving a
dossier owning nothing while the ledger still counts it.

**What it does not check, demonstrated.** Whether a claim is *true*. A dossier
was made to claim `arch/arm64/mmu.c`, which it has never swept; the file exists,
so the entry passes, and `mmu.c` moves from unowned to owned. The only failure
was the stale generated body — the count changed and the view had not been
re-rendered. That is a real but partial property: a false claim landed in a
commit that does not re-render is caught, one landed with a re-render is not.
**This ledger measures assertions, and a wrong assertion is what went wrong
upstream of it.** It beats the area-MOC criterion it replaces only because a
`code:` entry is a deliberate statement about a named file, where "the area has
children" was an accident of structure — a smaller gap, not a closed one.

Whether a dossier that genuinely covers a file *still* covers it after the file
changes is a different question, and it is now computed: `quaestor stale`
compares each dossier's `updated:` against the date every file it claims last
changed *on this branch*. The two ledgers answer different halves — this one
says every file has an owner, that one says whether the owner still tells the
truth — and the day it was first run, 84% coverage came with 45 of 112 dossiers
describing code that had moved underneath them. A high number here is not
evidence of currency, and was quietly being read as if it were.

Still unchecked by either: whether a dossier that covers a current file covers
it *well*.

**What it deliberately excludes.** Tests (`*/test*`), `usr/apps/**` (the aux
track's, per the branch boundary), and vendored trees. `tools/` is excluded
because the substrate is swept as harness prose rather than as owned translation
units — see [[sub-substrate-gates]] and its siblings.

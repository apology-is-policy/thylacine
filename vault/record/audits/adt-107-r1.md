## Scope

The mask-before-read fix in `sched()`, the loud-fail assert that the
locked per-CPU slot belongs to the running CPU, and the re-added
syscall-return preempt point at the vector level.

Opus-4.8-max prosecutor plus a concurrent self-audit; converged.

## Verdict

**0 P0 / 0 P1 / 1 P2 / 2 P3**, all fixed.

## Findings

- [[fnd-107-r1-f1]] (P2) — `ready_on` carried the **identical TOCTOU
  class**. This is the finding that mattered, and the disposition matters
  as much as the finding: it was fixed by masking first, **closing the
  class**, rather than by documenting an unstated caller precondition.
  Every live caller already masked (a `wakeup` holds the timer lock
  irqsave; the SVC spawners are hardware-masked), so a precondition
  comment would have been true and useless — a future IRQ-enabled kthread
  caller would have reintroduced it silently.
- **F2** (P3) — that masking only `I`, not `A`/`F`, is intentional and
  sufficient: the only migration vector in the window is a taken IRQ.
  Noted in-comment rather than changed.
- **F3** (P3) — an open-coded mask replaced with `spin_lock_irqsave(NULL)`.

## Evidence

The unusual part of this close is the negative control. The
previously-buggy mid-handler preempt placement was deliberately
**re-enabled** and the fix re-tested: 14/14 clean boots on TCG-smp4,
against a ~30–50% deadlock rate pre-fix. That is what established the
root fix, not the placement, was what mattered — and it is the reason the
syscall-return preempt could be restored rather than left removed.

Plus the standard matrix: 880/880, boot OK, login, and the SMP gate with
0 corruption across 40 boots.

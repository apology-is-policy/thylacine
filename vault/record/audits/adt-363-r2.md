is a change to a wait/park protocol.

## Verdict

**0 P0 / 0 P1 / 0 P2 / 1 P3.** Clean. The recursion stops here.

## Traced sound

Everything the round-1 fix could plausibly have broken:

- **Loop termination and progress** — a stale-TRUE pass consumes a real
  insert/steal pair and re-reads fresh heads; the keep-running return
  covers the truly-empty case.
- **`idle_in_wfi` is TRUE at every WFI commit** — the switch-site flag
  maintenance covers the loop's last iteration, and the explicit set
  covers the paths that never switched.
- The `cs` hoist (all three pin-enforcement points verified), the DAIF
  discipline (masked from entry through the WFI on every path), the
  telemetry semantics, test-phase neutrality, `need_resched` composition,
  extinction unreachability, and the masked-window bound.

## The finding

[[fnd-33-r2-f1]] — a *comment*, and worth a P3 anyway because of what it
would invite. It misattributed the [[inv-i9]] guarantee to a flag-gated
IPI. Ground truth: a peer that places **onto** another CPU IPIs
unconditionally; `idle_in_wfi` is read only by `select_idle_target` and
by the local-place notify. As written, the comment could invite a future
"optimization" that gates the cross-CPU placement IPI on the flag — whose
bare-volatile store a peer can read stale-FALSE — reintroducing
up-to-backstop placement latency, the exact class #363 had just closed.
The comment now names both paths and forbids the gate.

## Recorded, no action

[[spec-sched-tickless]] **cannot express** #363 — it has no self-requeue
action — so the whole spec family would stay green through a
reintroduction. Acceptable for a latency-class bug bounded by the
backstop, and written down so the next change to the park-commit logic
does not read a green spec run as coverage. Also noted: the sibling
surplus test carries a pre-existing unmasked window whose assertions are
interleaving-robust, unlike the one round 1 masked.

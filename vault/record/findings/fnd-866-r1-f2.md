## Prosecution

`try_steal` checked each band's **head only**: if the head was
`cpu_pinned`, it skipped the whole band. So a non-pinned thread queued
*behind* a pinned one — behind `kthread`, or behind a CPU's in-tree idle
in `BAND_IDLE` — was unstealable, and would sit on a busy CPU while an
idle peer looked at it and moved on.

This diverges from [[spec-sched-alpha]]'s `StealCand`, which admits **any
non-pinned runqueue member**. The impl was strictly weaker than the model
it is gated by — which is the kind of divergence that is invisible until
it matters, because the model does not check the impl.

## Fix

Walk the band list past pinned candidates and take the first non-pinned
one — which, because the list is `vd_t`-sorted, is still the lowest-key
eligible thread. The sort order is preserved.

## Reachability

Pre-existing (the retired `kstack_base` gate had the same head-only
scan) and **steady-state unreachable**: `kthread`'s `vd_t` bump sorts it
to its band's tail, and nothing non-pinned is ever placed in
`BAND_IDLE`. No v1.0 workload starves.

The reason it was fixed rather than documented: the head-only scan would
**silently strand** such a thread the day some path creates one, and the
symptom — a runnable thread that no idle CPU ever takes — is
indistinguishable from a scheduler that is simply slow. The same posture
as [[chg-2026-05-31-801-steal-claim]]: on this surface, a window whose
reachability depends on a *future caller* is a defect now.

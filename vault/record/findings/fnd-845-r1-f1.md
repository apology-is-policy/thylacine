## Prosecution

A NON-CONFORMANT server sending a duplicate Rflush after the flush tag was
freed and reused for a NEW flush frees the new flush's reserved oldtag --
wire-indistinguishable (9P has no per-tag generation).

## Disposition

Closed with justification (no client-side fix exists): this is the GENERIC
one-reply-per-tag assumption the whole client already rests on -- a
duplicate same-type reply mis-attributes for ANY op kind; #845 adds Rflush
to a pre-existing set, not a new hazard class. The in-tree guard is already
maximal (awaiting_flush only on a reserved normal op). v1.0-unreachable
(trusted servers); carried as [[seam-845-untrusted-server]] -- the v1.x
wire-tag-generation lift.

## Prosecution

#811 gave `proc_group_terminate` a precondition it never had: the caller
must hold [[lock-proc-table]], because the new cascade walks `p->threads`
and that list is mutated only under it. The #809-era smoke test called it
WITHOUT the lock.

Benign in fact — the test's Proc is a bare `proc_alloc` with an empty thread
list, so the walk touches nothing — but it models incorrect usage in the one
place a future author looks for an example.

## Disposition

FIXED: the two real-Proc calls wrapped in
`proc_table_lock_acquire`/`release`; the NULL fail-safe call left as-is
(it returns before the walk).

A test that demonstrates a contract violation is worse than no test, because
it is read as a specimen of correct use.

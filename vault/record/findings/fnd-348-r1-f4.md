## Prosecution

The blocking sends run deadline-0, so their TIMEDOUT branches are dead
defense-in-depth. If a future change arms a real server-side deadline,
the partial-count return is ambiguous to `write_full` — a deadline
expiry is indistinguishable from a short write, so the retry loop just
re-parks instead of surfacing the timeout.

## Disposition

Documented as a forward caveat at the dead branch: any server deadline
must land WITH a `server_timed_out` analog of `client_timed_out`. No
code — the branch as-is is correct for deadline-0. Carried on
[[sub-kernel-srvconn]]'s Caveats.

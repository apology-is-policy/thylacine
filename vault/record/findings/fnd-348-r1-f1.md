## Prosecution

The `writing` busy-guard returns −1 to a second concurrent blocking
writer on one s2c — and a 9P-server Proc's `write_full` treats −1
exactly as it treats 0: fatal → close the kernel-attached mount. The
very #348 cascade, one layer up. LATENT at the round: stratumd was
one-thread-per-conn, so no v1.0 path produced two writers; it mirrored
the already-shipped `reading` guard's same latent class. CF-2's threaded
request processing then made the kernel's soundness rest on stratumd's
own `write_mu` — a cross-project precondition.

## Disposition

Deferred at the round as the documented v1.0 SINGLE-WRITER PRECONDITION
+ task #354, deliberately NOT fixed then: unverifiable (no threaded-
server workload, no deterministic test) and "complexity only where
verified" forbids an unverified wait/wake mechanism on the most
bug-prone lineage. CLOSED by CF-3 B's #354 role park
([[chg-2026-07-08-cf3b-bulk-ring]]): contenders now PARK on the chan's
`role_waiters` and serialize per buffer — the cross-project reliance
retired. The self-audit had flagged the adjacent P3; the formal round
correctly elevated the mount-close chain to P2.

## Prosecution

client_send_flow parked every back-pressured sender on one shared
single-waiter send_rendez; the SECOND concurrent parker trips
extinction("sleep: rendez already has a waiter") -- an unprivileged,
SMP-reachable kernel panic on exactly the #349 workload (parallel go-build
writers filling the shared c2s while a third op reads; the client is shared
across every Proc resolving through the mount).

## Disposition

Fixed: send_rendez -> the multi-waiter `send_waiters_list`
(poll_waiter_list; each sender on its OWN stack rendez; the waker wakes
all). The self-audit had cleared this park by analogy to rpc->done -- wrong
because rpc->done is safe only since each rpc OWNS its rendez. The named
hazard class exists because of this finding.

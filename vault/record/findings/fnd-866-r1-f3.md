## Prosecution

`sched_capacity_init` (boot CPU, once) stored every CPU's normalized
capacity plainly and set `g_sched_hetero` plainly.
`select_target_cpu` (any CPU, any time) read both plainly.

On a weakly-ordered machine there is no edge forcing the capacity stores
to be visible before the flag. A cross-CPU reader could observe
`g_sched_hetero == true` and then read a **stale or torn** capacity — and
act on it, placing a thread according to a capacity that was never
written.

## Fix

Make the flag the publish point. `sched_capacity_init` writes every
capacity plainly, then **RELEASE**-stores `g_sched_hetero`;
`select_target_cpu` **ACQUIRE**-loads the flag *first* and only touches
a capacity when it reads true.

The ordering falls out of the control flow rather than being bolted on:
on a uniform topology the acquire short-circuits to `prev_cpu` before any
capacity is read at all, so the pairing costs nothing on every current
target and is correct the day a heterogeneous DTB activates it.

## Note

Dormant, like every #866 finding, because the whole HMP path is inert on
uniform hardware. Recorded as a memory-ordering *shape* worth reusing:
when a boot-time table is published to concurrent readers, give it one
flag that is the release/acquire point and gate every read of the table
on it, rather than fencing each entry.

V-3b-1c-1 turns V-3b-1b's one-shot guest-map probe into a persistent, reusable
ring ENGINE on main (`de6ed20f`, hash-fixup `1b2a54d3`), holotype CLEAN after
fixes (Fable 5, family diversity; 0 P0 / 0 P1 / 1 P2 / 3 P3, all fixed;
GL-verified on thyla-pi KVM/V3D). [[sub-tapestryd]] gains a "persistent ring
engine" section: the `HostmemAllocator` hoisted into a `Gpu.hostmem` field with
a first-fit free-list (reclaim on teardown), the reusable
`mint_host3d_ring`/`drop_host3d_ring` lifecycle, and a two-ring probe that
witnesses PHYSICAL distinctness + free-list reuse. The edge worth pinning, and
why F1 was the round's P2: a `Copy` `HostRing` + a by-`&ref` drop + an
unvalidated `free()` COMPOSE into a silent double-free that would alias two
clients' rings at one hostmem offset the day 1c-2 adds a second retire path --
three innocuous choices, no single one wrong, no log line when they combine. The
fix is the type system (drop `Copy`, drop by value -> a double-drop is a compile
error) plus a `free` oob/overlap guard; the reusable lesson is that a `Copy`
resource handle is a double-free waiting for a second caller. This change also
CORRECTS an inherited [[sub-tapestryd]] error the V-3b-1b F1 fix left behind: the
1b guest-map section said `burrow_from_hostmem(..., T_CACHE_WC)`, but that fix had
already changed the code to the host-dictated `map_info_to_cache` (CACHED on KVM,
the GPU-DESIGN 6.2 honored-exactly rule) -- the exact misleading-comment class the
F1 finding was about, updated in the code but not in the dossier. WARP-V3-DESIGN
section 0.7 carries the same stale WC claim and is corrected on main alongside.
The `SYS_BURROW_FROM_HOSTMEM` client binding remains owned by
`sub-kernel-syscall-abi` (lib.rs) + `sub-libthyla-rs` (hardware.rs), unchanged
here; the client-claimable `/srv/warp` ring (the weft-share of the hostmem burrow
+ the per-client venus device-ctx + the `warp-prove` cross-Proc leg) is V-3b-1c-2.

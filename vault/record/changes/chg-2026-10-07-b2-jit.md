B-2's two kernel sub-chunks, landed together: the region JavaScriptCore will
JIT into (B-2c) and the hardening of its writer alias, by the operator's votes
of 2026-09-28 (the lazy code Burrow; the writer hardened inside B-2) and
2026-10-07 ([[dec-2026-10-07-jit-sealed-thunk]],
[[dec-2026-10-07-loom-register-errno]], [[dec-2026-10-07-maps-code-redaction]]).

**B-2a: the code region is a reservation** ([[sub-kernel-burrow]],
[[sub-kernel-fault]], [[sub-kernel-mm-phys]]). A code Burrow allocates a
pagemap and no page; the first touch through either alias commits the page,
charges it once and invalidates it before any leaf maps it; destroy refunds
the footprint (resident pages and pagemap nodes). SYS_ICACHE_SYNC syncs only
committed pages, and a CPU with a non-PIPT instruction cache makes every sync
invalidate the whole I-cache (Linux's sync_icache_aliases). Every release path
still refuses code: a decommit through one alias would leave the other's leaf
on a freed page.

**B-2b: the writer alias hardened** ([[sub-kernel-mmu]], [[sub-kernel-uaccess]],
[[sub-kernel-syscall-abi]]):

- Each alias of a code region lands at its own random address in the window
  (a random start, the first gap at or above it), so a leaked exec address
  says nothing about the writer's.
- `SYS_JIT_CREATE_SEALED` (127) copies a thunk into a region born sealed: one
  execute-only alias (AP=10, UXN clear), no writer ever, filled and synced
  before any mapping exists. Execute-only exists only over a code Burrow;
  every other X-without-R still maps R+X.
- Every user copy the kernel makes on EL0's behalf is `LDTR`/`STTR`, checked
  against EL0's own permissions, and the debug reader refuses a leaf EL0
  cannot read.
- `/proc/<pid>/maps` prints a code row's addresses only to the target itself
  or a reader with debug authority over it; any other reader gets each code
  row zeroed, after every other row, grouped by permission, and only when the
  walk completed ([[sub-kernel-devproc]]).
- The I-39 image join counts a space holding a code alias as carrying
  `CAP_JIT` (`AddrSpace.code_vmas`; [[sub-kernel-proc]], [[sub-kernel-vma]],
  [[sub-kernel-addrspace]], [[sub-kernel-caps]]): an `RFMEM` child keeps its
  creator's aliases after the creator is reaped, and without this a capless
  same-principal peer covered it (audit r2, self-found). The diorama refuses
  to serve while it holds any elevation-only cap, so it is never shown a code
  address it could pass on ([[sub-diorama]]).
- `SYS_LOOM_REGISTER` returns -errno, the failed flush's own errno included;
  a caught note that interrupts a write-behind flush keeps the staged run
  instead of latching EINTR ([[sub-kernel-loom]], [[sub-kernel-ninep-dev9p]]).

Audits: B-2a round 1 (Fable 5.1, 0/0/2/2); B-2b round 1 (Fable 5.1, 0/0/0/4,
F2 widened to the maps vote), round 2 (Fable 5.1, 0/0/0/3, widened by the join
defect), round 3 (Fable 5.1, 0/0/0/3); closed. The clade bake ran llvmpipe's JIT from random aliases
some 46 TiB apart: ORC/JITLink needs no near placement.

## Corrections (the record plane is append-only, so they live here)

**[[dec-2026-10-07-loom-register-errno]]'s Fork said "a death's EINTR".** A
death fails the flush with EIO: the Tflush a dying thread's unwind sends takes
the request back as never sent (-P9_E_IO), and the dying caller never reads the
result. EINTR is a caught note's; since B-2b the write-behind flush keeps the
staged run when the thread holds a note claim, so the next flush resends it,
and a server's own Rlerror(EINTR), with no claim behind it, latches like ENOSPC
(audit r1 F1). LOOM.md 8.1 was corrected in place.

**212f8e479 (the B-2a audit close) said "no kernel test drove an instruction
fetch at all".** Overclaimed from a one-spelling grep: test_demand_page.c's
`make_fi` drives fetches. What was true is narrower: no test drove a fetch
through a code region's exec alias, which `jit.fetch_admission` now does.

**[[dec-2026-10-07-maps-code-redaction]]'s Option 1 said "unless the reader
passes the I-39 predicate".** The code always also shows a Proc its own code
rows: I-39 refuses a NOTRACE Proc even to itself, and a Proc's own layout tells
no one else anything. The dec also omits the budget-stop residual its dossier
states, and its Tree facts left the diorama at "reads as ITSELF", the argument
audit r2 found stale (above).

## Residuals

- `status`'s `tables:` and `pages:` and the `/ctl/procs` table count page
  tables, ambiently. They say how many 512 GiB, 1 GiB and 2 MiB spans the
  aliases occupy, never where; the one placing case is an alias in the
  window's first 508 GiB sharing the low mappings' top table, about 0.8% of
  placements, which gives about 7 of its 34 bits. Linux's `VmPTE` is the same.
- maps' budget stop: a space with more code aliases below its last printed
  row than the buffer holds 26-byte zeroed rows (77) prints no code
  row, and where the walk stopped says something about where they lie.
- A Proc holding a live code region cannot fork (the clone classifier refuses
  CODE; B-2a audit F3): B-2c must keep the web process from forking after JSC
  reserves its pool.
- B-2c must keep `/proc` out of the web content process's namespace: an
  in-process attacker with file access reads its own maps.
- An `RFMEM` child keeps an I-34 MMIO/DMA/HOSTMEM mapping after its driver is
  reaped, and the cover does not weigh it (audit r3 F3; the same class as the
  code-alias defect, pre-existing). Enqueued in OPEN-BUGS, owned by main: the
  count trick does not transfer, because an allowance's authority is per
  allowance.

# 122 — `libthyla_rs::net`: the native TCP/UDP/ICMP client [ABSORBED INTO THE VAULT]

Absorbed at the docs/reference retirement (`chg-2026-09-07-net-doc-absorb`).
The native (libthyla-rs, `no_std`) `std::net`-shaped client over netd's `/net`
tree — `TcpStream`/`TcpListener`, `UdpSocket`, `IcmpSocket`, `SocketAddrV4`. There
are **no socket syscalls** by commitment (ARCH §11.5, NOVEL #1): a native program
reaches TCP/IP the Plan 9 way, walking the connection-server tree with
`open`/`read`/`write`/`close`. Its content lives, code-verified and current, in:

- the **`/net` protocol itself** — authoritatively on the *server* side, which
  *defines* what the client mirrors: the clone idiom (open `clone` → mint N →
  rebind the fid onto `N/ctl`), the ctl verbs (`connect a.b.c.d!port`,
  `announce *!port`, `hangup`), the `N/{ctl,data,local,remote,status,err,ready}`
  layout (+ `listen` on TCP), the `ready` readiness sibling (net-6b — poll *that*,
  not the always-ready 9P `data` fd, for a bounded read or POLLOUT write-room),
  the deferred-reply connection lifecycle, and the refcounted table whose
  last-clunk frees connection N:

      vault/system/userspace/services/sub-netd-server.md   (audit: hard)

- the **`ping` / IcmpSocket recv seam #256** — an ICMP *error* response
  (Destination Unreachable) that quotes our ident makes the socket readable, so
  `recv` consumes it, finds it is not an EchoReply, and blocks (interruptibly) for
  the next packet; a host that answers only with an ICMP error waits out its poll.
  The silent-host case is bounded by the poll timeout; the per-recv deadline is
  the v1.x fix:

      vault/system/userspace/services/sub-netd-server.md   (the ping seam #256)

- the **runtime principles the client composes** — RAII over the handle table (a
  dropped stream/listener/socket, or any error-path early return, leaks no fd and
  so no netd slot), the single error decoder, and the ISV-safe MMIO discipline —
  and the deliberate **scope** that the typed per-module API surface is the code's
  own (its rustdoc), not a separately-catalogued vault section:

      vault/system/userspace/runtime/sub-libthyla-rs.md

- the **`sntp` / `net-echo` consumers** — the deterministic-selftest-vs-live split
  every standalone net client shares, the sntp clock-step *denial* self-test (the
  sharpest gate in the group), **and now the sntp trust model**: the per-request
  originate-nonce that defends against an off-path spoofer, the on-path attacker as
  the documented boundary (NTS is the v1.x hardening), and the era-2036 saturating
  1900->Unix conversion:

      vault/system/userspace/tools/sub-net-clients.md   (the SNTP trust model — folded here)

**What this file got WRONG or MISSED by the time it was absorbed:**

- **One genuine gap, now folded — the SNTP security posture.** `sub-net-clients`
  carried the clock-step denial self-test but not *why* an unauthenticated time
  source can be trusted at all: the originate-nonce off-path-spoof defense, the
  on-path documented boundary + the NTS v1.x seam, and the era-2036 saturating
  conversion were homeless. They are now in `sub-net-clients`
  (`chg-2026-09-07-net-doc-absorb`).
- **The `/net` protocol table is the client's *view*; the authority is the
  server.** netd *defines* the clone idiom, the ctl verbs and the readiness split;
  `net.rs` is a typed mirror of it. So the protocol content redirects to
  `sub-netd-server`, which additionally carries the connection-lifecycle hazards
  the doc did not (`#257` the SynSent premature-Rlopen, `#293`/`#239` the connect
  deadline + the FK_LISTEN rw-mode) — the server dossier is *ahead* of this doc.
- **The typed client API surface + its defensive reply-parse guards
  (`read_decimal` overflow-guard, `read_endpoint` bound, the address range checks)
  are net.rs's own code**, owned by `sub-libthyla-rs`'s code list and described by
  its rustdoc. `sub-libthyla-rs` states plainly that it catalogs what the library
  *adds*, not per-module APIs — so the API shape is not lost, it is deliberately
  code-level. Zero code change.

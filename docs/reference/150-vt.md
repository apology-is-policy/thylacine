# 150 -- vt: the shared VT/xterm escape-sequence parser

## Purpose

`usr/lib/vt` is the terminal escape-sequence interpreter: a byte stream in, a
cell grid out. It is the SCREEN side of the terminal protocol (the app side is
Kaua's emitter). One `Vt` owns a `cols x rows` grid of `Cell`s, a cursor, an
SGR pen, an alternate screen, and a small reply buffer for the queries a real
terminal must answer (CPR). It is a shared crate (since HALCYON section 13.4):
aurora hosts one `Vt` per surface; halcyond hosts one per raw-VT pane; the
coming kaua-term hosts one per tile. It is `#![no_std]` + alloc and pure logic
-- the pixel side (the atlas blit) stays with each consumer, so the parser is
host-tested (`cargo test -p vt --target aarch64-apple-darwin`).

It consumes an UNTRUSTED byte stream (any Linux TUI, any program with terminal
write access), so its governing invariant is TOTALITY: no byte sequence may
panic, out-of-bounds index the grid, or wedge the parser. It ships under
overflow-checks, where an arithmetic overflow is a panic that would take the
shared console down. This is why it is in the format-fuzz audit class
(HALCYON section 14.10).

## Public API

```rust
pub const BG: u32; pub const FG: u32;        // Bonfire default ground/ink
pub struct Palette { bg, fg, ansi: [u32; 16] }
pub const BONFIRE: Palette;                  // the default palette
pub const DAYLIGHT: Palette;                 // KT-1.5d-2: the Halcyon render palette

// Cell attribute bits. 0..=6 are SGR pen bits (owned by SgrPen); bit 7 is
// cell geometry (the parser sets it, the pen never does).
pub const ATTR_REVERSE  = 1 << 0;
pub const ATTR_UNDERLINE = 1 << 1;
pub const ATTR_BOLD     = 1 << 2;
pub const ATTR_ITALIC   = 1 << 3;   // KT-1a-4
pub const ATTR_DIM      = 1 << 4;   // KT-1a-4
pub const ATTR_BLINK    = 1 << 5;   // KT-1a-4
pub const ATTR_STRIKE   = 1 << 6;   // KT-1a-4
pub const ATTR_WIDE     = 1 << 7;   // KT-1a-3: left half of a double-width glyph

pub struct Cell { pub ch: char, pub fg: u32, pub bg: u32, pub attrs: u8, pub span: u32 }
                                               // span: H-4d-2b, see the cell model
pub struct SgrPen { pub fg: u32, pub bg: u32, pub attrs: u8 }
impl SgrPen { pub fn new(pal) -> SgrPen; pub fn apply(&mut self, pal, params: &[u32]); }

pub struct Vt { /* grid, cursor, pen, alt screen, osc/utf8 state, reply */ }
impl Vt {
    pub fn new(cols: usize, rows: usize) -> Vt;   // dims clamped to >= 1 (== with_palette(.., BONFIRE))
    pub fn with_palette(cols, rows, pal: Palette) -> Vt;  // KT-1.5d-2: born in `pal`
    pub fn resize(&mut self, ncols: usize, nrows: usize);
    pub fn feed(&mut self, bytes: &[u8]);         // the parser entry point
    pub fn set_theme(&mut self, idx: usize);
}
```

The consumer reads `Vt.cells` (row-major, `cy*cols + cx`), `Vt.cx`/`Vt.cy`,
`Vt.cursor_visible`, and drains `Vt.reply` (the CPR answer) onto the keyboard
wire. Aurora reads only `ch` + `ATTR_REVERSE`/`ATTR_UNDERLINE` today; the other
attr bits are retained by the parser for a wide/attr-aware renderer (KT-1c/1d).

## Escape-sequence coverage

Printable text is decoded from UTF-8 (a 1--4 byte assembler; a malformed
sequence yields U+FFFD, never a panic) and placed via `put_char`.

- C0 controls: BS, HT (8-col tabs), LF/VT/FF (`line_feed`), CR, BEL (OSC
  terminator), SO/SI + ESC-charset designators swallowed.
- CSI cursor: A/B/C/D (rel move, clamped), G (CHA), d (VPA), H/f (CUP), s/u
  (SCOSC/SCORC position-only).
- CSI edit: J (ED), K (EL), L (IL), M (DL), @ (ICH), P (DCH), X (ECH). IL/DL
  are confined to the scroll region (a no-op when the cursor is outside it);
  each repeat count is clamped to the grid remainder (bounded work).
- CSI scroll: **S (SU) / T (SD)** -- scroll the DECSTBM band by n, cursor
  unmoved, n clamped to the band height. CSI T is SD only in its 0/1-param
  form; the 5-param form (xterm highlight mouse tracking) is ignored.
- CSI **r (DECSTBM)**: set the scroll region [top,bot] (1-based; empty or
  malformed -> full screen; homes the cursor origin-aware).
- CSI n (DSR 6 = CPR): answers `ESC [ row ; col R` into the reply buffer.
- CSI h/l private modes: **?6 (DECOM origin)**, ?7 (DECAWM autowrap), ?25
  (cursor visibility), ?47/1047/1049 (alternate screen, 1049 = implicit
  DECSC/DECRC).
- CSI m (SGR): 0 reset; 1 bold, **2 dim, 3 italic**, 4 underline, **5/6 blink**,
  7 reverse, **9 strike**; **22 clears bold AND dim**, 23/24/25/27/29 clear
  italic/underline/blink/reverse/strike; 30-37/39/90-97 fg, 40-47/49/100-107 bg,
  38/48 extended color (`;5;n` xterm-256 cube, `;2;r;g;b` truecolor pass-through).
- ESC: M (RI, region-aware), c (RIS full reset), ( ) charset designator
  (swallowed), OSC intro.
- OSC 7770 (`OSC 7770;aurora;<key>;<value>`, BEL or ST terminated): the aurora
  settings channel (bounded queue, cap 16; control bytes rejected -- the
  cfg-3 F1 laundering guard). Other OSC (titles) swallowed.

Unknown finals/sequences are parsed to completion and dropped -- never a
desync.

## The cell / wide-glyph model (KT-1a-3)

`char_width(c)` returns the display width: 0 for combining / zero-width marks,
2 for East Asian Wide/Fullwidth + the supplementary emoji planes, else 1. It
follows Markus Kuhn's reference wcwidth ranges (`is_wide` + the sorted
`COMBINING` table; `in_ranges` binary-searches the latter, whose sorted,
non-overlapping invariant is asserted by `combining_table_is_sorted`).
`COMBINING` is consulted BEFORE `is_wide`, so a combining mark that falls
inside a wide block (e.g. U+302A..302D, U+3099..309A) correctly returns 0.

A double-width glyph occupies two cells: the LEFT half carries the char plus
`ATTR_WIDE`; the RIGHT half is a blank continuation carrying the pen (so
reverse video / bg cover both halves) and is NOT marked wide. A wide glyph
never straddles the right margin -- with autowrap it moves whole to the next
line, without it degrades to a clamped single-width paint. In a terminal too
narrow to ever hold one (`cols < 2`) a wide glyph is shown single-width.
Combining / zero-width marks take no column (no cell, no advance).

**The span serial (H-4d-2b, 2026-09-05).** `Cell.span` is the serial of the
last Beacon frame (an OSC whose code is `1936`) the parser forwarded before
the cell was written -- 0 until the first frame; blanks from erase / scroll
fill carry 0. The parser keeps `span` / `span_serial`, advances them when a
1936 OSC terminates in capture mode (a numeric selector on the body's prefix;
the body is never interpreted -- the Beacon parser stays in the consumer,
R5), and reports the serial on the boundary (`Boundary::Osc { serial, body }`,
0 for any other OSC). A scroll carries the stamps with the row
(`Boundary::Scroll`). The consumer (halcyond) feeds the same frames in order
and maps a serial to the span state after that frame, so a cell knows its
presentation (obj / em / hdr) however late it leaves the screen. Host test:
`beacon_frames_stamp_cells_with_the_span_serial`.

## State machine

- Ground -> Esc -> Csi/Osc/EscCharset, plus Utf8 assembly, plus the OSC
  ST-terminator sub-state. `feed` drives one byte at a time (`byte`).
- Scroll region [scroll_top, scroll_bot] (0-based inclusive; default
  [0, rows-1]); `line_feed` scrolls the band when cy == scroll_bot; RI scrolls
  it down when cy == scroll_top; DECOM origin remaps CUP/VPA into the band.
  DECSTBM validates top < bot < rows or resets to full. `resize` and RIS reset
  the region to full.
- The alternate screen swaps `cells`/`alt_cells`; 1049 does an implicit
  DECSC/DECRC of cursor + autowrap (the G-5 F5 wrap-leak fix).

## Tests

`usr/lib/vt/src/lib.rs` `mod tests` (host target): the deferred-wrap + OOB
regressions (G-4 F1), CSI param overflow, OSC settings, CPR, theme remap, and
the KT-1a set: DECSTBM confine/malformed/resize, DECOM region-relative CUP, RI
region scroll, SU/SD confine + cursor-hold + clamp + 5-param guard, wide-char
advance/mark/continuation + margin-wrap + no-wrap-degrade + cols<2 degrade,
combining-no-column, `combining_table_is_sorted`, `char_width` spot-checks, and
SGR italic/dim/blink/strike + the 22-clears-both rule.

## Error paths / totality

There are no `-EXXX` returns; the contract is totality. Every grid write goes
through `write_cell` at an index proven `< cells.len()` by the cursor
containment invariant (cx in [0,cols], cy in [0,rows-1]); every repeat count is
clamped to the grid remainder; UTF-8 and CSI-param accumulation are bounded.

## Known caveats / footguns

- **DECOM confines addressing, not relative moves**: origin mode remaps and
  clamps CUP/VPA into the band, but CUU/CUD/CUF/CUB are not region-confined --
  a full-DECOM refinement, deferred (no in-tree consumer sets DECOM).
- **SU/SD by a huge count** iterate the band scroll up to the band height (the
  clamp bounds the work); a single band-clear when `n >= band` would remove the
  fold -- deferred as negligible.
- The consumer must clamp when reading `cx` in the deferred-wrap state
  (`cx == cols`); the parser holds the cursor there intentionally (DECAWM).
